# PaperLocus（Hermes Agent 中文适配版）

将每篇论文定位在文献图谱中，而非仅仅总结摘要。
这是 PaperLocus 的 Hermes Agent 中文适配版。原版 Codex skill 见 `../paperlocus/SKILL.md`。

> 📝 **English users**: use [`SKILL.md`](SKILL.md) for English output.

## 工作模式

- 将此 skill 视为整篇论文阅读和文献定位工作流。
- 输出语言：中文。
- 从论文本身出发建立理解。
- 优先产出可复用的 Markdown 笔记，而非一次性散装总结。

## 上下文构建策略

- 除非用户明确要求全文深度阅读，否则不要将整篇论文塞入上下文。
- 优先分层构建上下文：
  1. 当前论文的标题、摘要、引言主张、方法框架和核心实验
  2. 一小部分核心相关文献，而非整个参考文献列表
  3. 一份记录论文定位和洞察的可复用 Markdown 笔记
- 优先关注：
  1. 引言中明确讨论或批评的论文
  2. 实验中反复使用的强基线
  3. 仅限用户当前研究的同一狭窄子领域

## 输入获取

- 接受 PDF、本地文件、arXiv 链接、DOI、网页、截图或纯标题输入。
- 有全文时优先使用全文。
- 如果只有标题或部分内容，先恢复最少必要的缺失上下文，再做强力断言。
- 如果某些章节缺失或不可读，明确说明并缩小总结范围。

### 按输入类型的处理方式

- **PDF 或本地文件：**
  - 使用 `pymupdf`（fitz）或 `pdfplumber` 提取文本。如需安装：`pip install pymupdf`。
  - 先提取标题、摘要、章节标题、引言、方法、实验和结论。
  - 跳过致谢、检查清单和模板文字，除非它们确实重要。
- **arXiv 链接、DOI 链接或网页：**
  - 先恢复文献元数据和正文或摘要，再做总结。
  - 优先使用论文本身而非第三方评论。
  - 使用 arXiv API（`https://export.arxiv.org/api/query?...`）或 `web_search` 获取。
- **截图：**
  - 使用 `vision_analyze` 读取截图。
  - 将截图视为部分证据。
  - 除非截图确实覆盖了所需章节，否则不要假装理解整篇论文。
- **纯标题请求：**
  - 先通过 web_search 或 arXiv API 恢复摘要级上下文和基本元数据。
  - 如果论文正文仍不可获取，给出有范围的预判笔记，而非自信的全篇概述。

## 第一决策：判断论文类型

- 判断论文是遵循计算机科学会议/arXiv 叙事逻辑，还是 Nature/Science 族叙事逻辑。
- 如果类型不明确，说明不确定性，并默认走计算机科学工作流，除非论文明显围绕科学发现和证据链组织。
- 确定分支前使用以下检查清单。
- 具体区分案例见 [references/paper_type_examples.md](references/paper_type_examples.md)。

### 论文类型分类检查清单

**优先走 CS 会议/arXiv 分支**，如果以下多数为真：
1. 摘要围绕新模型、算法、框架、基准或训练配方展开
2. 论文结构类似 `引言 → 相关工作 → 方法 → 实验 → 结论`
3. 引言花了大量篇幅批评已有方法并论证技术设计
4. 核心证据是基线对比、消融实验、缩放曲线和基准指标
5. 贡献表述为"我们提出"而非"我们发现"或"我们揭示"

**优先走 Nature/Science 族分支**，如果以下多数为真：
1. 摘要围绕一项科学发现、机制或关于世界的实证主张展开
2. 论文结构围绕发现和证据组织，而非独立的方法章节
3. 引言强调科学问题、知识空白或竞争性解释
4. 核心证据是支撑结论的累积实验链、观测或测量
5. 贡献表述为"我们发现"、"我们揭示"或"我们证明了 X 成立"，方法服务于发现

**混合情况：**
- 如果论文发在科学期刊但读起来仍像方法论文，按叙事逻辑分类，不唯期刊。
- 如果论文为科学领域提出方法，问自己：核心产出是工具还是科学结论？
- 不确定时，说明哪些信号冲突，然后选择最匹配结果部分组织方式的分支。

## 计算机科学会议/arXiv 工作流

- 只要原文支持，将论文解释为「在 A 的基础上，改了 B，因此得到了 C」。
- 提取：
  - 核心子方向
  - 论文批评的关键前置工作
  - 提出的框架
  - 主要声称贡献
- 对于实验，解释：
  - 每个实验为什么存在
  - 它旨在支撑哪个主张
  - 哪些指标和基线至关重要

## Nature/Science 族工作流

- 识别核心科学问题。
- 说明论文挑战、扩展或填补了哪些既有认知。
- 将关键发现与获取发现的方法分开。
- 解释每个主要实验或数据集旨在证明什么。
- 重建支撑核心结论的证据链。
- 说明机制层面的解释、适用范围和局限性。

## 防幻觉规则

- 当需要精确性时，分离**论文主张**、**证据**、**推断**和**开放问题**。
- 不编造论文或经验证来源不支持的前置工作联系、指标、数据集、实现细节或创新声明。
- 广义理解"幻觉"：
  - 不仅是捏造事实
  - 也包括扭曲论文在领域中的定位
  - 也包括抹去研究者自然会用到的比较要点的摘要

## 输出模板

使用紧凑笔记，包含以下章节：

- **一句话总结**
- **论文卡片** — 标题、作者、发表地、年份、输入条件
- **论文类型** — 方法论文 / 证据链论文 / 混合型
- **文献位置** — 在 A 的基础上，改了 B，得到了 C
- **引言主线** 或 **科学问题**
- **方法框架**
- **实验设计与核心结果**
- **主要贡献**
- **局限、反例与检查点**
- **值得细读的部分**

当输入不完整时（纯标题、截图、仅摘要），明确标注笔记级别（如"title-only smoke test"）并分离论文主张与推断。
